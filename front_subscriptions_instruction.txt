ИНСТРУКЦИЯ ДЛЯ ФРОНТЕНДА: ИНТЕГРАЦИЯ АБОНЕМЕНТОВ

Этот документ описывает все изменения в существующих эндпоинтах и новые эндпоинты для поддержки системы абонементов (покупка пакетов часов и оплата слотов корта накопленными часами).


==================================================================
1. ИЗМЕНЕННЫЙ ЭНДПОИНТ: POST /get-full-price
==================================================================

Когда вызывается:
Пользователь выбрал дату, локацию и слоты времени и переходит на экран подтверждения/оплаты брони.

ВАЖНО: Теперь в тело запроса обязательно нужно передавать telegram_id пользователя (число), чтобы бэкенд мог проверить наличие у него активного абонемента и оставшихся часов.

Запрос:
POST {base_url}/get-full-price
Content-Type: application/json

Тело запроса:
{
  "location": "A",
  "day": "2026-11-20",
  "telegram_id": 123456789,
  "time_slots": {
    "10:00-11:00": 1,
    "11:00-12:00": 1
  }
}
Ответы:

200 OK
{
  "temporary_order_id": "nanoid_строка_заказа",
  "location": "A",
  "time_slot": "10:00-12:00",
  "price": 300000,
  "can_pay_with_subscription": true,
  "subscription": {
    "available_hours": 5.0,
    "required_hours": 2,
    "can_pay": true,
    "remaining_after_payment": 3.0
  }
}

Пояснение к новым полям в ответе:
- can_pay_with_subscription: булево значение (true / false). Показывает, хватает ли у клиента часов абонемента для полной оплаты выбранных слотов.
- subscription.available_hours: сколько всего доступных оплаченных часов сейчас есть у клиента.
- subscription.required_hours: сколько часов требуется для оплаты выбранных слотов.
- subscription.can_pay: дублирует can_pay_with_subscription (true / false).
- subscription.remaining_after_payment: сколько часов останется у клиента на балансе абонемента после этой оплаты.

400 Bad Request
{
  "error": "Missing required fields"
}

409 Conflict
{
  "message": "Слоты уже успели занять к сожалению...."
}

500 Internal Server Error
{
  "error": "Текст ошибки"
}

ЧТО ДЕЛАТЬ ВО ФРОНТЕНДЕ:
2. Если can_pay_with_subscription == true:
   - Отобразить кнопку "Оплатить абонементом (с баланса спишется X ч., останется Y ч.)".
   - Эта кнопка активна. При нажатии на неё вызывать новый эндпоинт POST /pay-with-subscription (описан в пункте 2).
3. Если can_pay_with_subscription == false:
   - Если subscription.available_hours > 0: можно показать кнопку "Оплатить абонементом" заблокированной (disabled) с текстом: "Недостаточно часов на абонементе (нужно X ч., доступно Y ч.)" и рядом ссылку/кнопку "Купить абонемент".
   - Если subscription.available_hours == 0: можно скрыть вариант абонемента или показать неактивным с кнопкой "Купить абонемент".
   - Или просто оплатить саму сумму самому переводом на карту(ну как обычно).


==================================================================
2. НОВЫЙ ЭНДПОИНТ: POST /pay-with-subscription
==================================================================

Когда вызывается:
Когда пользователь на экране подтверждения брони выбрал оплату абонементом и нажал кнопку "Оплатить абонементом".

Запрос:
POST {base_url}/subscriptions/pay-booking
Content-Type: application/json

Тело запроса:
{
  "booking_id": "temporary_order_id_полученный_из_get_full_price",
  "telegram_id": 123456789
}

Ответы:

200 OK
{
  "status": "success",
  "message": "Бронь успешно оплачена абонементом",
  "order_id": "id_брони",
  "remaining_hours": 3.0
}

400 Bad Request (если часы закончились или их не хватает)
{
  "error": "Недостаточно часов на абонементе",
  "available_hours": 1.0,
  "required_hours": 2
}

404 Not Found (если бронь не найдена или истекли 4 минуты таймера)
{
  "error": "Бронь не найдена или истекло время холдирования"
}

500 Internal Server Error
{
  "error": "Текст ошибки"
}

ЧТО ДЕЛАТЬ ВО ФРОНТЕНДЕ:
1. При нажатии "Оплатить абонементом" отправить запрос на /pay-with-subscription.
2. При статусе 200 OK:
   - Показать красивый экран успешной оплаты и бронирования: "Бронь успешно подтверждена! Списано X ч. Остаток на абонементе: Y ч."
   - Кнопка "Перейти на главную".
   - Пользователю в этот момент Telegram-бот также присылает сообщение с деталями бронирования - но это уже бэкенд делает, не твоя зона.
3. При статусе 400 Bad Request:
   - Показать сообщение, что часов недостаточно, и предложить купить абонемент либо оплатить переводом на карту.
4. При статусе 404 Not Found:
   - Сообщить, что время бронирования истекло, и вернуть пользователя на экран выбора слотов.


==================================================================
3. ИЗМЕНЕННЫЙ ЭНДПОИНТ: GET /profile/{telegram_id}
==================================================================

Когда вызывается:
При открытии раздела "Профиль".

Запрос:
GET {base_url}/profile/{telegram_id}

Параметры URL:
telegram_id (integer) — Telegram ID пользователя.

Ответы:

200 OK
{
  "name": "Имя пользователя",
  "phone": "+998901234567",
  "bookings": [
    {
      "date": "2026-11-25",
      "location": "A",
      "telegram_id": 123456789,
      "time_slot": "10:00-11:00",
      "booking_id": "id_брони"
    }
  ],
  "subscription": {
    "has_subscription": true,
    "available_hours": 8.0,
    "active_subscriptions": [
      {
        "id": 1,
        "subscription_id": 2,
        "name": "Абонемент 10 часов",
        "total_hours": 10,
        "remaining_hours": 8.0,
        "purchased_at": "2026-11-10 12:00:00",
        "expires_at": "2026-12-10 12:00:00",
        "status": "active"
      }
    ]
  }
}

Пояснение к новому блоку subscription в профиле:
- subscription.has_subscription: булево значение. true, если у пользователя есть хотя бы один действующий абонемент с остатком часов > 0.
- subscription.available_hours: суммарный баланс часов по всем активным абонементам.
- subscription.active_subscriptions: список активных абонементов:
  * id: ID записи абонемента пользователя
  * subscription_id: ID базового тарифа
  * name: название тарифа (например, "Абонемент 10 часов")
  * total_hours: сколько всего часов было куплено
  * remaining_hours: сколько часов осталось
  * purchased_at: дата покупки (YYYY-MM-DD HH:MM:SS)
  * expires_at: дата окончания действия (если null — абонемент бессрочный)
  * status: статус ("active")

404 Not Found
{
  "error": "Пользователь не найден"
}

ЧТО ДЕЛАТЬ ВО ФРОНТЕНДЕ:
1. В профиле добавить блок "Мой абонемент":
   - Если has_subscription == true:
     Отобразить красивую карточку абонемента:
     * Баланс: "Осталось: X часов"
     * Название абонемента
     * Если expires_at != null, показать дату окончания: "Действует до DD.MM.YYYY"
     * Если expires_at == null, показать "Бессрочный"
     * Кнопка "Купить еще абонемент" (переход в каталог абонементов).
   - Если has_subscription == false:
     Отобразить блок с предложением: "У вас нет активного абонемента" и заметную кнопку "Купить абонемент".

4. НОВЫЙ ЭНДПОИНТ: GET /subscriptions (КАТАЛОГ АБОНЕМЕНТОВ)
==================================================================

Когда вызывается:
Когда пользователь нажимает кнопку "Купить абонемент" и открывает каталог доступных абонементов.

Запрос:
GET {base_url}/subscriptions/available

Ответы:

200 OK
[
  {
    "id": 1,
    "name": "Абонемент 10 часов",
    "hours": 10,
    "price": 500000,
    "description": "10 часов игры на кортах локации A и B",
    "days_valid": 30,
    "is_active": 1,
    "created_at": "2026-11-12 18:00:00"
  },
  {
    "id": 2,
    "name": "Абонемент 20 часов",
    "hours": 20,
    "price": 900000,
    "description": "20 часов игры, действует 60 дней",
    "days_valid": 60,
    "is_active": 1,
    "created_at": "2026-11-12 18:00:00"
  }
]

Пояснение к полям:
- id: числовой ID тарифа (нужен для передачи при покупке)
- name: название тарифа
- hours: количество часов
- price: цена в сумах
- description: текстовое описание тарифа
- days_valid: срок действия в днях (если null — бессрочный)

ЧТО ДЕЛАТЬ ВО ФРОНТЕНДЕ:
1. Отобразить каталог карточек абонементов.
2. В каждой карточке показать:
   - Название
   - Количество часов
   - Цену
   - Срок действия ("30 дней" или "Без ограничений")
   - Описание
   - Кнопку "Купить".
3. При нажатии на "Купить" переходить на экран оплаты абонемента (пункт 5).

5. НОВЫЙ ЭНДПОИНТ: POST /subscriptions/buy (ОТПРАВКА ЧЕКА НА АБОНЕМЕНТ)
==================================================================

Как работает покупка абонемента:
Клиент выбирает абонемент, видит реквизиты карты для оплаты (или переводит деньги), прикрепляет фото/скриншот чека перевода и нажимает "Отправить". Бэкенд сохраняет заявку и отправляет фото чека администратору в Telegram с кнопками подтверждения.

Запрос:
POST {base_url}/subscriptions/buy
(Алиас: POST {base_url}/subscriptions/buy-subscription)
Content-Type: multipart/form-data

Параметры формы (form-data):
- photo: файл изображения (jpg, png) — скриншот или фото чека оплаты (ОБЯЗАТЕЛЬНО)
- subscription_id: числовой ID тарифа абонемента (ОБЯЗАТЕЛЬНО)
- telegram_id: Telegram ID пользователя (ОБЯЗАТЕЛЬНО)
- price: строка или число, сумма платежа (НЕОБЯЗАТЕЛЬНО, по умолчанию берется цена тарифа)

Ответы:

200 OK
{
  "success": true,
  "purchase_id": "nanoid_строка_покупки",
  "message": "Чек на покупку абонемента принят и отправлен администратору на проверку"
}

400 Bad Request
{
  "detail": "Missing user telegram id"
}
или
{
  "detail": "This subscription is currently inactive"
}

404 Not Found
{
  "detail": "Subscription not found"
}

500 Internal Server Error
{
  "detail": "Текст ошибки"
}

ЧТО ДЕЛАТЬ ВО ФРОНТЕНДЕ:
1. Экран покупки выбранного абонемента:
   - Отобразить выбранный тариф (название, часы, сумма к оплате).
   - Отобразить реквизиты для перевода (номер карты, имя получателя) - как обычно у нас.
   - Поле выбора файла / фото чека (input type="file" accept="image/*").
   - Кнопка "Отправить чек".
2. При нажатии "Отправить чек":
   - Сформировать FormData с полями photo, subscription_id, telegram_id.
   - Отправить POST {base_url}/subscriptions/buy.
3. При получении 200 OK:
   - Показать экран успешной отправки: "Чек успешно отправлен администратору! После подтверждения оплаты часы будут начислены на ваш баланс, а бот пришлет вам уведомление."
   - Кнопка "Вернуться в профиль" или "На главную".

7. СВОДНАЯ СХЕМА ПУТЕЙ ПОЛЬЗОВАТЕЛЯ (USER FLOWS)
==================================================================

СЦЕНАРИЙ А: ПОКУПКА АБОНЕМЕНТА
1. Пользователь заходит в Профиль -> нажимает "Купить абонемент".
2. Фронтенд вызывает GET /subscriptions и отрисовывает карточки тарифов.
3. Пользователь выбирает тариф -> видит реквизиты для перевода и загружает чек.
4. Фронтенд отправляет POST /subscriptions/buy (multipart/form-data).
5. Фронтенд показывает сообщение "Чек отправлен на проверку администратору".
6. Админ в Telegram нажимает кнопку подтверждения -> бот присылает пользователю уведомление "Абонемент активирован!".

СЦЕНАРИЙ Б: БРОНИРОВАНИЕ КОРТА С ОПЛАТОЙ АБОНЕМЕНТОМ
1. Пользователь выбирает локацию, дату и слоты времени.
2. Фронтенд отправляет POST /get-full-price с telegram_id.
3. В ответе бэкенд возвращает can_pay_with_subscription: true и блок subscription.
4. Фронтенд показывает сумму и кнопку "Оплатить абонементом (2 ч.)".
5. Пользователь нажимает "Оплатить абонементом".
6. Фронтенд отправляет POST /pay-with-subscription с booking_id и telegram_id.
7. Бэкенд списывает часы, регистрирует бронь в календаре и возвращает 200 OK с новым remaining_hours.
8. Фронтенд показывает экран успеха с остатком часов. Бот в Telegram также дублирует подтверждение бронирования.
